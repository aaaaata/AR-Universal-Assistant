# AR 麻将助手 Android 工程结构说明

> 基准日期：2026-09-07  
> 工程根目录：`new/armahjongassist-develop-huangwl/`  
> 目标：先建立模块边界和文件职责的整体概念，再逐模块评审实现是否合理。

## 1. 先看整体分层

```text
app（产品壳、生命周期、权限、UI）
 |-- sdk-bundle（完整 SDK 的聚合依赖入口）
 |    |-- sdk-core（稳定契约、状态机、能力租约）
 |    |-- sdk-cv（视觉场景公共处理骨架）
 |    |-- sdk-network（通用 HTTP 客户端基础设施）
 |    |-- sdk-platform-android（Android 通用能力实现）
 |    `-- sdk-device-rayneo-x3（RayNeo X3 厂商适配）
 `-- scene-mahjong（麻将业务场景插件）
      |-- sdk-core
      |-- sdk-cv
      `-- sdk-network
```

各层的判断标准：

| 层 | 应该知道什么 | 不应该知道什么 |
| --- | --- | --- |
| `app` | Android 页面、权限、生命周期、安装哪些场景 | 相机采集细节、麻将 HTTP 字段、识别规则 |
| `sdk-core` | 场景和能力的抽象契约、状态与资源所有权 | Android API、RayNeo API、麻将业务 |
| `sdk-cv` | CV 场景共同的选帧、单飞、取消、清理流程 | 某个具体业务的请求和结果格式 |
| `sdk-network` | Retrofit/OkHttp 创建和请求追踪元数据 | 麻将 endpoint、API Key 的具体用法 |
| `sdk-platform-android` | 如何用 Android API 实现通用能力 | RayNeo 手势和麻将业务 |
| `sdk-device-rayneo-x3` | Mercury SDK 初始化与输入映射 | 通用状态机和麻将业务 |
| `scene-mahjong` | 麻将协议、云端会话、结果映射和场景 UI | Activity 生命周期和设备厂商 SDK |
| `sdk-bundle` | 对外一次性暴露哪些 SDK 模块 | 任何运行时业务逻辑 |

## 2. 一次真实运行如何穿过这些模块

```text
AssistApplication
  -> MercurySdkInitializer

MainActivity
  -> MainViewModel
  -> AppHost
  -> CoreSceneEngine
  -> MahjongSceneProvider / CVSceneProvider
  -> Camera2Capability
  -> FrameProcessingGate
  -> MahjongProcessor
  -> RetrofitMahjongGateway
  -> 云端 /api/v1/mahjong/*
  <- AnalyzeResponse
  -> MahjongResultMapper
  -> SceneResult / SdkEvent
  -> MainViewModel
  -> SceneRenderRouter
  -> MahjongSceneRenderer
  -> 眼镜画面
```

启动场景时，Core 一次性申请 Camera、Network 等能力租约；停止、异常或 App 退后台时释放。相机虽然持续采集，但 `FrameProcessingGate` 保证满足采样间隔且上一帧处理结束后，下一帧才进入上传链路。

## 3. 标记说明

| 标记 | 含义 |
| --- | --- |
| `[主链路]` | 当前麻将闭环直接执行或直接依赖 |
| `[支撑]` | 构建、装配、兼容性或工程治理所需，不直接处理一帧数据 |
| `[可选能力]` | Core 契约和 Android 默认实现均已具备，但当前麻将不使用或只声明为 optional |
| `[测试]` | 验证契约和关键行为，不进入正式 APK 运行逻辑 |
| `[资料]` | 文档、截图、日志、生成源或本地分析产物，不参与运行 |

标记表示当前定位，不表示文件可以直接删除。例如权限模型文件虽然很小，但权限功能仍是主链路的一部分；是否需要单独成文件要在后续结构评审中判断。

### 4.3 `sdk/sdk-bundle`：完整 SDK 聚合入口

这个模块与其他 SDK 模块并列，是因为它本身也是一个可被 Gradle 依赖的交付模块；但逻辑上它位于其他 SDK 模块的上层。它没有 Kotlin 实现，不参与运行时编排。

```text

```

### 4.9 `scene-mahjong`：麻将业务场景插件

```text

|-- build.gradle.kts                              [支撑] 公开 core/cv，内部依赖 network 和 Gson，启用 ViewBinding
`-- src/
```

## 5. 最重要的边界

建立心智模型时，先记住下面五点：

1. `sdk-bundle` 只是发布/依赖聚合入口，不是另一个 Android Runtime，也没有运行逻辑。
2. 当前 9 项标准 Capability 都已有 Android 默认实现；但“代码存在”不等于自动运行，仍需场景声明、Factory 注册、权限/硬件可用并取得租约。
3. `sdk-platform-android` 负责 Android 通用实现，`sdk-device-rayneo-x3` 只负责 RayNeo/Mercury 差异，两者不能混为一层。
4. `CVSceneProvider` 管公共帧流程，`MahjongSceneProvider` 管麻将策略；相机和并发逻辑不应回流到麻将模块。
5. `app` 是产品装配点。新增场景通常是新增 `scene-*` 模块，并在 `AppHostFactory` 注册，而不是继续增大 `MainActivity`。

## 6. 云端边界

本说明只展开 Android 工程。当前 Android 客户端通过 `scene-mahjong/service/MahjongApi.kt` 访问外部云端：

```text
POST /api/v1/mahjong/sessions
POST /api/v1/mahjong/sessions/{session_id}/frames
POST /api/v1/mahjong/sessions/{session_id}/end
```

云端代码位于工作区的 `armahjongassist-server-dev-caolx/cloud/`，是独立工程和独立运行边界，不属于上述 8 个 Android Gradle 模块。需要评审服务端时，应单独按照 HTTP 入口、业务编排、模型适配、结构化/规则和持久化五层展开。
