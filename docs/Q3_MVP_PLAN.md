# AR麻将助手 项目规划文档

## 项目背景

基于创新应用组的落地项目需求，进行 AR 麻将助手的相关开发。

## 当前进度

核心链路打通，有最基础的 Demo 可以试用，但还未达到 MVP 的标准。

## 需求分析

用户在使用眼镜打麻将时，需要在不影响本身麻将体验的前提下，对牌型进行识别、分析和建议。核心需求至少包括：

1. UI 不遮挡视野，保持中低存在感
2. 牌型识别要准，识别时间和准确率要平衡在每一圈的间隔内（3-10 秒给出准确的牌型识别和胡牌建议）
3. 算法服务的具体形式待定（手机 App / 云服务）

## 成熟方案设想

### 1. 基础能力

- 实时牌效与建议
- 全局场况感知，实时追踪四家明牌数据
- AI 对手建模
- 新手教学

### 2. 感知强化（可自由开关）

- 视觉效果
- 听觉伴随（特定牌型音效、专属 BGM 等）
- 解说模式

### 3. 数据复盘

- 依据基础能力的四方牌型计算
- 战报卡片（四方全局），MVP / "最惨受害人"等趣味称号
- 赛后复盘，关键决策点分析
- 专属云房间 + 好友观战

### 4. 情绪价值

- UI 主题设计
- 场景模式（麻将馆 / 家庭麻将）

### M0：实机冒烟（目标 7/21）

**目的**：让 APP 能在眼镜上跑起来，整个链路首次打通，不管识别好不好、延迟大不大，通就行。

**已完成：**

- [x] 编译通过，APK 装到 X3 眼镜上能正常启动
- [x] 扫码连接流程打通（浏览器生成 QR 码 → 眼镜扫码 → 自动连接）
- [x] 摄像头预览 + 自动循环拍照正常工作（Camera2，720p，1fps）
- [x] 拍照→上传→YOLO 识别→结果显示，全链路跑通
- [x] WSL2 网络隔离问题已解决（Windows 端口转发 + 防火墙规则）
- [x] 手机展示麻将图片测试，识别效果可用

**M0 实机发现：**

| 发现 | 影响 |
|------|------|
| RayNeo X3 相机是定焦镜头，无自动对焦 | 距离太近（<20cm）会虚焦，正常打牌距离（40-70cm）在焦段内 |
| README 描述的手势（三击开始/单击拍照）未实现，实际是自动循环拍照 | 用户无需手动触发，进入流式模式后自动抓拍 |
| WSL2 开发环境下服务器 IP 为虚拟网络地址，眼镜无法直连 | 需配置 Windows 端口转发 |

**待完成：**

- [ ] 修复 `build.gradle.kts` compileSdk 语法问题
- [ ] 用实物麻将牌（非手机屏幕图片）做首次实机测试
- [ ] 整理实机问题清单（什么 work，什么不 work）

**产出**：一个能跑通的 APK + 实机问题清单

---

### M1：核心链路可用（目标 8/4）

**目的**：拍照→识别→牌效→建议，这条链路在实机上稳定可用，每次都能跑完，不是"偶尔行"。

**任务拆解：**

- [ ] **手势交互补完**：实现 RayNeo SDK 镜腿手势（三击右侧开始/结束对局、单击拍照），当前为占位代码
- [ ] **服务端 bug 修复**：图片保存失败后不应继续处理流程，需中断并返回错误
- [ ] **端到端延迟测量**：从拍照到眼镜显示建议的完整耗时，确认是否在 3-10 秒可接受范围内
- [ ] **实物麻将测试**：用真实麻将牌或打印图片在眼镜下测试，确认基本识别可用
- [ ] **连接稳定性**：连续运行 10 分钟不掉线、不卡死

**产出**：一个人能独立完成一回合拍照→切牌的完整操作

---

### M2：识别与牌效调优（目标 8/18）

**目的**：把识别率调到可用水平，切牌建议合理，为 M3 鸣牌联调打好基础。

**任务拆解：**

- [ ] **阈值调优**：调整 YOLO 的 conf_threshold / iou_threshold，适配 720p 实拍照片和定焦镜头特性
- [ ] **建立测试集**：用实拍样本收集至少 50 张照片（不同手牌组合、不同光照条件）
- [ ] **识别率达标**：手牌准确率 >80%（MVP 门槛），输出统计报告
- [ ] **定焦场景优化**：确认最佳拍摄距离范围，评估是否需要模糊样本做数据增强
- [ ] **牌效走查**：选取 20 种以上典型手牌场景（含听牌、多面待ち等），逐一手动验证切牌建议合理
- [ ] **修复已知 bug**：`test_efficiency_simulation.py` 方法名错误等

**产出**：识别和牌效在非极端条件下表现可接受，输出准确率报告

---

### M3：鸣牌与对局流程（目标 9/1）

**目的**：不止手牌识别，碰/吃/杠等副露操作也能正确处理，能完整打完一局。

**任务拆解：**

- [ ] **副露识别验证**：在实机上逐一测试 Pon（碰）、Chi（吃）、Daiminkan（大明杠）、Kakan（加杠）、Ankan（暗杠）的拍照检测
- [ ] **状态追踪修复**：修复实机测试中发现的状态机 bug（副露后手牌数变化、振听判断等）
- [ ] **完整对局测试**：至少完整打 2 局真实对局，记录所有异常行为
- [ ] **会话管理稳定**：开始/结束对局流程反复测试，确保不卡死、不丢状态、不残留数据
- [ ] **边界场景覆盖**：立直后识别、海底牌、流局等特殊场景

**产出**：能完整打完一局，鸣牌建议不出大错，异常记录文档

---

### M4：MVP 冻结（目标 9/15）

**目的**：锁定范围，只修阻断性问题，产出可交付内部测试的版本。

**任务拆解：**

- [ ] **严重 Bug 清零**：修复 M3 阶段发现的所有阻断性（功能不可用）Bug
- [ ] **中低优先级挂起**：非阻断问题全部记录，不修但标记清楚
- [ ] **已知限制清单**：输出一份文档，列明当前版本的已知短板（如弱光下识别率下降、多人语音未支持、仅支持日麻规则等）
- [ ] **版本冻结**：打出 0.1.0 版本标签，不再接受新功能需求

**产出**：一个可交付内部测试的 APK（v0.1.0）+ 已知限制清单

## Phase 2：年前打磨（10 月 - 春节前）

## 风险清单

| 风险方向 | 举例 |
|----------|------|
| 硬件限制 | 定焦镜头导致近距离虚焦；720p 分辨率上限 |
| 模型精度 | YOLO 在小牌面/遮挡/弱光下识别率不达标 |
| 环境适应 | 不同光照、牌背颜色、桌面反光 |
| 交互体验 | RayNeo SDK 稳定性、手势误触 |
| 工程风险 | Camera2 兼容性、服务端到手机端的迁移成本 |
| 项目风险 | 人力不足、排期紧张 |
