### Frame 流与多帧交换语义

```text
Camera2.capture
  -> Camera2FrameScheduler.frames(): Flow<Frame>
  -> MahjongSceneProvider.start().collect
  -> MahjongCloudService.submitImage
  -> POST /api/v1/mahjong/sessions/{session_id}/analyses
  -> SceneResult
  -> SdkEvent.ResultReceived
  -> MainActivity 当前结果区域
```

- Flow 使用顺序 `emit`：只有当前 Frame 完成读取、上传、映射和临时文件删除后，调度器才等待
  下一采集周期，因此同一场景不会并发提交多帧。
- 一次场景只创建一个云端 session，多帧复用该 session；停止、后台、取消或错误时调用
  `/end` 并释放 Camera2。
- `ConnectionConfig.serverUrl` 映射到 `MahjongSceneConfig.serverBaseUrl`，FPS 映射为采集间隔；
  API Key 不写入场景普通配置。

### API Key 配置

- `local-token` 是本地开发服务与客户端约定的访问凭据，不是麻将 session ID。
- `server/run_local.py` 默认设置 `CLOUD_API_KEY=local-token`；客户端默认构建也使用
  `LOCAL_API_KEY=local-token`，并通过 `X-API-Key` 请求头发送。
- 云端当前可在构建时通过 `-PCLOUD_API_KEY=<云端实际值>` 覆盖；若云端部署也配置为
  `local-token`，则默认构建可直接验证。
- `/health/ready` 不校验此凭据；创建 session、上传分析和结束 session 都会校验。

- 本阶段复用现有结果文本区域进行链路验证，没有迁移最终麻将 HUD 视觉与交互。

1. `python -m server.run_local` 能启动服务并输出局域网二维码页面 URL。
2. `/health/live` 返回 `live`，模型加载成功时 `/health/ready` 返回 `ready`。
3. 浏览器打开 `/debug/connect?api_key=local-token` 能显示二维码。
