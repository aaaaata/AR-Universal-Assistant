# 场景职责分离改造计划（待确认）

本文是下一步改造的设计说明，不代表已经完成的迁移记录。目标是将本地/云端服务选择、二维码连接和普通/录制开局从 `app` 完全迁入 `scene-mahjong`，同时保留新框架的场景可插拔能力。

## 目标边界

| 模块 | 改造后的职责 | 不应包含的职责 |
|---|---|---|
| `app` | 场景列表、场景模块发现与注册、通用内容容器、Core 装配、Android/RayNeo 生命周期、`TempleAction` 到 `InputAction` 的转换、相机和真实凭据值的宿主注入 | 本地/云端页面、二维码页面、麻将模式页面、连接配置状态、模式 ID、麻将手势语义、二维码协议解析 |
| `sdk-core` | 场景注册、Core 状态机、Session、Frame Flow、背压、资源租约、事件分发、通用场景启动入口和通用凭据请求 | 二维码、HTTP 就绪检查、本地/云端概念、麻将模式、麻将配置字段、麻将页面 |
| `scene-mahjong` | 连接方式、本地配置、二维码扫描、普通/录制选择、服务就绪检查、麻将配置构造、麻将 Session、HUD、麻将运行态输入和云端业务会话 | Camera2 实现、RayNeo SDK 直接监听、Core 状态机和资源释放 |

App 中的场景列表继续保留。它只显示 `SceneModule` 注册的 `ScenePresentation`，用户点击某个 `sceneId` 后，App 挂载该场景提供的启动入口；列表不包含任何麻将连接或模式业务。

## 目标流程

```text
App 场景列表
  -> 用户选择 mahjong
  -> App 创建 Mahjong 启动入口并挂载到通用容器
  -> Mahjong 启动入口自行管理：连接方式 -> 配置/扫码 -> 模式选择
  -> Mahjong 启动入口产出 MahjongSceneConfig
  -> App 仅调用 core.startScene("mahjong", config)
  -> Core 管理 Session、帧流、资源和状态
  -> MahjongSession 管理云端麻将会话、HUD 和运行态输入
  -> 会话停止后，App 卸载场景内容并回到场景列表
```

启动前和运行中都只有一个眼镜事件来源：App 从 RayNeo SDK 获得 `TempleAction` 并转换为 `InputAction`。转发目标取决于通用阶段，而不取决于麻将业务语义：

| 通用阶段 | 唯一输入目标 | 语义由谁定义 |
|---|---|---|
| 场景列表 | App 的通用菜单 | App |
| 已选中场景但尚未调用 `core.startScene()` | 当前场景的启动入口 | 场景模块 |
| Core `STARTING` / `RUNNING` | 当前 Core Session | 场景 Session |

因此同一个事件不会同时交给启动入口和 Core。麻将启动入口可以定义滑动切换模式、单击选择、双击确认；麻将 Session 可以定义三击退出或后续 HUD 手势。App 不再写死这些规则。

## 最小契约调整

当前第 8 阶段加入的 `SceneConnection`、`SceneStartMode` 和 `SceneLaunchProvider` 的 `supportedConnectionSceneIds` / `startModes` / `createSceneConfig(connection, startModeId)`，是为了让 App 渲染麻将连接和模式页面而加入的。它们当前只有麻将使用，继续保留会让 `sdk-core` 承担启动业务字段。

这个改造时将保留 `SceneLaunchProvider` 作为可选扩展，但把它收缩为通用启动入口工厂；不再由 Core 定义连接或模式字段。拟定形态如下：

```kotlin
interface SceneLaunchProvider : SceneProvider {
    fun createLaunchController(): SceneLaunchController
}

interface SceneLaunchController {
    fun attach(
        activity: Activity,
        container: ViewGroup,
        onStart: (SceneConfig) -> Unit,
        onExit: () -> Unit
    )

    fun onInput(action: InputAction)
    fun close()
}
```

这里的 `SceneLaunchController` 是通用契约：它不包含二维码、服务模式、页面数量或麻将字段。没有启动页的场景可以不实现 `SceneLaunchProvider`，App 直接以默认 `SceneConfig` 调用 `core.startScene()`。

`MahjongLaunchController` 由 `scene-mahjong` 实现，页面资源、跳转状态、输入规则和 `MahjongSceneConfig` 构造全部在麻将模块中。App 只调用 `attach`、转发输入，并在回调中执行 `core.startScene()` 或返回菜单。

## 二维码与连接配置迁移

以下内容从 `app` 移至 `scene-mahjong`：

- `QrScanActivity`、二维码扫描布局、相关 drawable/string 和模块 Manifest 声明；
- ZXing 依赖；
- `ServerConnectionQrParser`；
- `ConnectionConfig`、`ConnectionConfigStore`；
- `LocalServiceConnector`、`CloudServiceConnector`、`ServiceReadinessProbe`；
- 本地/云端连接页面、扫码页面、普通/录制模式页面及其 UI 状态；
- 连接和模式相关单元测试。

Android Library 可以声明自己的 `QrScanActivity`；其 Manifest 会在构建 App 时自动合并。因此二维码模块可物理上完全位于 `scene-mahjong`，不需要在 App Manifest 中保留 Activity 声明。

连接配置持久化改为麻将模块的私有存储，仅保存服务地址、服务类型、采集频率等非敏感数据。二维码和持久化配置不得包含 API Key。

`MainActivity` 将删除连接、扫码、云端状态和模式选择的 `UiMode`、View、按钮监听、焦点索引及页面跳转。其布局只保留场景列表、通用场景内容容器和运行态结果容器。

## 凭据标识调整

`CredentialProvider` 是 `sdk-core` 中的通用接口契约。它的目的是让场景取得凭据，而不让场景知道真实 Key 的来源或把 Key 写入普通配置。

当前接口只有 `credentialFor(sceneId)`，而 App 通过 `activeConfig.serviceMode` 选择 `LOCAL_API_KEY` 或 `CLOUD_API_KEY`。这会使 App 持有麻将连接状态，需改掉。

改造后：

1. `SceneConfig` 增加可选的通用 `credentialId`，默认值为 `null`。该字段是标识，不是密钥值。
2. `CredentialProvider` 改为接收 `sceneId` 和 `credentialId`；Core 只把场景配置的标识转交给 Provider。
3. `MahjongSceneConfig` 根据所选服务声明 `mahjong.local` 或 `mahjong.cloud`。
4. App 的 Provider 只将这些不透明标识映射为 `BuildConfig.LOCAL_API_KEY` 或 `BuildConfig.CLOUD_API_KEY`，不读取 `MahjongSceneConfig`，不维护当前连接页面状态。

```text
MahjongSceneConfig.credentialId = "mahjong.local"
  -> Core / SceneContext
  -> CredentialProvider.credentialFor("mahjong", "mahjong.local")
  -> App 返回真实 LOCAL_API_KEY
```

真实密钥值仍由 App 的构建配置或宿主安全存储注入；这不代表 App 拥有本地/云端页面业务。场景只声明本局需要哪一种凭据。

## 运行态输入和停止

本次职责分离同时完成此前已识别的运行态输入边界：

- `MahjongSceneProvider.requiredCapabilities` 增加 `INPUT`；
- App 负责把 RayNeo 事件转换为 `InputAction`，Core 在运行态将其路由给当前麻将 Session；
- Mahjong Session 解释运行态手势，例如三击退出；
- 场景通过 `SceneContext.requestStop()` 请求停止，不能直接取消 Core、相机或资源；
- Core 负责取消 Session、停止 Frame Flow、关闭资源、回收状态；
- 停止逻辑必须覆盖 `STARTING` 和 `RUNNING`，确保启动过程中退出也最终回到 `READY`，不允许卡在 `STARTING`。

启动入口的输入不进入 Core；只有在 `core.startScene()` 后才进入 Core Session。

## 不在本次改造中处理的内容

- 不增加新的网络 SDK 模块；麻将网络、二维码和连接逻辑仍在 `scene-mahjong`。
- 不将 API Key 写入二维码、普通连接配置、日志或页面状态。
- 不改变 Core 对相机、Frame Flow、背压、资源租约和 Session 收尾的职责。
- 不改变 App 的场景发现和场景列表职责。
- 不处理尚未定义的其他场景页面；其他场景可不实现启动入口，或以后实现自己的 `SceneLaunchController`。

## 实施顺序与验收

1. 调整 Core 启动入口和凭据标识契约，先补对应单元测试。
2. 在 `scene-mahjong` 实现 `MahjongLaunchController`，迁移连接/二维码/模式配置和资源。
3. 将二维码 Activity 和依赖迁入麻将模块，确认 Manifest Merge 后可正常启动扫码页。
4. 删除 App 中对应页面、连接状态和业务依赖，仅保留通用场景容器和模块发现。
5. 接入运行态 INPUT 与 `STARTING` 停止收敛。
6. 更新迁移记录，并在眼镜上验证：本地扫码、保存配置、云端连接、普通/录制启动、三击结束和返回场景菜单。

验收标准是：在 `app` 源码和资源中搜索不到二维码页面、连接页面、模式名称、`ConnectionConfig`、`ServiceMode`、麻将二维码协议解析或 `MahjongSceneConfig`；App 仅通过通用场景契约加载麻将模块。
